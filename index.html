How mobile apps shape a digital cityPerformance

once it’s rolled out and stable

Next job: make it faster and steadier

Open fast

How long until you can use the app?

what we can do:

Start only what is needed

Delay setting up things the first screen does not use, so the app opens sooner.

Profile it

Record while the app starts: Android Studio Profiler, Xcode Instruments or Flutter DevTools show where the time goes.

Stay smooth

Stutters and freezes (“jank”) are felt right away

what we can do:

Find the bottleneck

Do not guess. A screen janks because heavy work runs on the main thread, so move it to the background.

Cache what repeats

Keep data and images you already fetched, so the next visit does not wait on the network.

Stay small

Download size, storage and battery add up

what we can do:

Use remote resources

Load banners and big images from the server when needed, so the download stays small.

Remove what is unused

Shrink code and unused libraries, and compress images, so the app gets smaller.
